# Adding products to the Optional tab (BU Konfigurator)

How to add a product — from the Vigor DB or by hand — to a category on the Optional
tab, create a new category, or add a sub-group like "Erforderliches Zubehör".
Everything here is `src/public/index.html` + `src/public/script.js` plus one DB row.

**TL;DR for the common case:**

```bash
node scripts/add-product.mjs COAIR40 --group=optBasin
```

then paste the two printed snippets (HTML tile → the right `menu_X` panel, JS lines →
`script.js`) and reload. Details, edge cases and the pitfalls follow.

Line numbers below are from 2026-07-31 and drift — every one of them is given with
its symbol name, search for that instead (`grep -n "const CAT_MENU" src/public/script.js`).

---

## 0. How it works (read once, saves hours)

```
opt_<ID> checkbox (name="optX[]") + qty_<ID> input      ← the only two inputs a product needs
   ↓  must be inside <form id="form-optional">
formToObject(#form-optional)  →  payload.optional  →  saved on the offer
   ↓
src/logic/pricing.js collectSelections(): walks every opt_<k> / qty_<k> key,
strips the prefix and looks the rest up in the Products collection by productId
   ↓
line price = Products.price × qty        → Kostentabelle, PDF, DOCX (all the same source)
```

Three consequences worth memorising:

1. **`<ID>` in `opt_<ID>` / `qty_<ID>` *is* the `productId`.** No mapping table
   exists. Typo in the id = product silently prices at 0.
2. **Prices never come from Vigor at offer time.** Vigor is a separate read-only
   DB used as a *catalogue source*; the app prices from its own `Products`
   collection. A product missing there shows up but costs nothing.
3. **Nothing else needs registering.** Badges, the chip bar ("Ausgewählte
   Optionen"), the in-panel search and the PDF/DOCX all derive from the DOM and
   from `pricing.js` output. There is no product list to maintain.

### The category layout

Each category is a card (`cat_X` checkbox) in `#optCategories` plus a panel

neighbours in the panel use.**

## 1. Step 1 — get the product into the `Products` collection

### 1a. Product is in the Vigor DB

```bash
node scripts/add-product.mjs COAIR40                 # one
node scripts/add-product.mjs CLPWCF10 WCBF CLPSSI    # several
node scripts/add-product.mjs COAIR40 --dry           # look only, write nothing
```

The script:
- reads the article by `articleNumber` from Vigor (read-only, `VIGOR_MONGODB_URI`)
- upserts `{ productId, name, price, source: "vigor" }` into `Products`
  — `price` is Vigor's **`netPrice`**, i.e. net/VAT-exclusive, which is what this
  codebase stores in `price` everywhere
- downloads `images[0]` to `src/public/assets/<ID>.jpg` (skips if the file exists)
- prints the ready HTML tile and the JS lines

Re-running is safe (upsert by `productId`), so it is also the way to refresh a price.

Useful flags: `--group=optBasin` (puts the right `name` in the printed snippet),
`--manufacturer="GC"`, `--dry`.

### 1b. Product is *not* in Vigor (manual)

```bash
node scripts/add-product.mjs \
  --id=DUSCHKORB02 \
  --name="Duschkorb Edelstahl mit Haken" \
  --price=24.90 \
  --image=/Users/you/Downloads/korb.jpg     # local file OR https:// URL, optional
```

- `--id` becomes the `productId` — pick something short and stable
  (`A-Z0-9_-`); it ends up in `opt_<id>`, `qty_<id>`, the Hassmann cart and the PDF.
- `--price` is **net**, decimal point (`24.90`, not `24,90`).
- `--image` is copied/downloaded to `src/public/assets/<ID>.jpg`. Without it the
  snippet falls back to `./assets/vk-brutto.jpg` — replace that with a real image
  when you have one; the frame is `aspect-ratio: 4/5` with `object-fit: contain`,
  so any proportion just letterboxes and you never need to resize a file.
- `source` is set to `"manual"` (existing values: `hassmann`, `vigor`).

Dimensions (`widthCm`/`heightCm`/`lengthCm`) are optional and only used by a few
Badewannen/Duschwannen flows — skip them for accessories. If you need them, add
them via the Admin panel (`/admin/`) or edit the row there.

> **Hassmann Warenkorb CSV:** items with an empty `manufacturer` are *included* in
> the export. If an article is not orderable at Hassmann, set
> `--manufacturer="GC"` (any non-Hassmann value) — see
> `src/routes/material-overview.js:35`. Vigor articles that Hassmann also carries
> can stay empty.

### 1c. Verify the row

```bash
curl -s localhost:3000/api/products/COAIR40   # needs a logged-in session
```
or open `/admin/` → Produkte, search the id. Wrong price → re-run the script or
fix it in the Admin panel.

## 2. Add a product to an **existing** category

Three edits. All three are needed; skipping one fails quietly in a different way.

### 2.1 HTML — the tile

In `src/public/index.html`, find the panel (`menu_BASIN`, `menu_REHA`, …) and add
inside its grid/flex container:

```html
<div class="opt-item">
  <label class="image-check">
    <input type="checkbox" id="opt_COAIR40" name="optBasin[]"
      value="Handwaschbecken Connect Air 40x35 cm 1 Hahnloch mit Überlauf weiß Ideal Standard COAIR40" />
    <span class="img-wrap"><img src="./assets/COAIR40.jpg" alt="COAIR40" /></span>
    <span class="caption">Handwaschbecken Connect Air 40x35 cm weiß COAIR40</span>
  </label>
  <div id="qty_COAIR40_wrap" class="field" hidden aria-hidden="true" style="max-width: 220px">
    <label for="qty_COAIR40" class="req">Menge COAIR40</label>
    <input id="qty_COAIR40" name="qty_COAIR40" type="number" min="0" step="1" placeholder="0" />
  </div>
</div>
```

Rules that are not optional:
- ids exactly `opt_<ID>`, `qty_<ID>`, wrapper `qty_<ID>_wrap` — `wireTileQty()`
  and `resetPanel()` derive names from that pattern.
- `name="qty_<ID>"` on the number input (same as its id).
- `value="…"` is the text that lands in the offer/PDF — **write it in German and
  end it with the article code**, that is the house style.
- `.caption` is what the user sees on the tile; short version, code at the end.
- Do not put the tile outside `<form id="form-optional">` — nothing outside that
  form is collected.
- The `.opt-item` wrapper is what the in-panel search filters on (badge and chips
  count checked checkboxes, so they work either way). Some old panels use
  `<div class="field">` instead; new tiles should use `.opt-item`.

> **Where exactly in the file?** Panels sit in the HTML source inside
> `#form-optional` right after `#optCategories`. At runtime `initOptionalUX()`
> *moves* every panel into the modal (`#optModalBody`). DevTools therefore shows
> them somewhere else — always edit the original spot in the source, never the
> modal markup.

### 2.2 JS — show the Menge field

`src/public/script.js`, next to that category's other calls:

```js
wireTileQty("opt_COAIR40", "qty_COAIR40_wrap");
```

Most categories wire theirs inside `initOptionalMenus()`; `cat_REHA` does it in a
flat block just below that function. Either place works — put it with its siblings.
Missing this: tile is checkable, the Menge field never appears, qty stays empty.

`wireTileQty` also sets qty to `1` on check and back to `0` on uncheck, and adds
`required` while checked.

### 2.3 JS — the two kid lists

Append `"opt_COAIR40"` to the category's array in **both** places:

- `ensureOptionalParentsSelected()`, `map` (~`script.js:14075`) — restores
  `cat_X` when a saved offer is reloaded
- `parentToKids` (~`script.js:18106`) — auto-checks `cat_X` when the user picks a
  product

Miss the first and reloaded offers open with the category card unchecked; miss the
second and picking a product from search/deep link leaves the card unchecked.

## 3. Add a **new** category

1. **Card** in `#optCategories`:
   ```html
   <label class="image-check">
     <input type="checkbox" id="cat_NEW" />
     <span class="img-wrap"><img src="./assets/NEW.jpg" alt="Neue Kategorie" /></span>
     <span class="caption">Neue Kategorie</span>
   </label>
   ```
2. **Panel** after the other `menu_*` divs, still inside `#form-optional`:
   ```html
   <div id="menu_NEW" class="full field" hidden aria-hidden="true">
     <div class="subheader">Neue Kategorie</div>
     <div class="opt-grid" style="display:flex;flex-wrap:wrap;gap:14px">
       <!-- tiles from §2.1, name="optNew[]" -->
     </div>
   </div>
   ```
   `class="full"` matters: the form is a 2-column grid, `full` spans the row.
3. **Register it in BOTH maps** — this is the number one mistake on this tab:
   - `map` in `initOptionalMenus()` (~`script.js:17221`) → show/hide + reset on deselect
   - `CAT_MENU` in `initOptionalUX()` (~`script.js:20227`) → modal, badge, chips, search

   Only in `map`: the modal never opens. Only in `CAT_MENU`: deselecting stops
   resetting the panel.
4. Wire every tile (§2.2) and add a `parentToKids["cat_NEW"]` + a
   `map.cat_NEW` entry in `ensureOptionalParentsSelected` (§2.3).
5. Search box: appears automatically, but only if the tiles are `.opt-item`
   elements inside a `.opt-grid` container and there are ≥ 8 of them
   (`SEARCH_MIN_ITEMS`, `script.js:20244`). Panels built from a plain flex div, or
   with tiles classed `field` instead of `opt-item` (as `menu_BASIN` does), get no
   search — use `.opt-grid` + `.opt-item` in new panels.

**Do not add a `display:` rule scoped by id** (like `#page-Optional .my-menu
{ display: grid }`) — see the pitfall list, that exact pattern leaked the WC panel
into other dialogs.

## 4. WC is different: JS-generated tiles

`menu_WC` has no static product tiles. It has `Montageart`
(Wandmontage/Bodenmontage), `Sitzhöhe`, and a container that
`wireWcMenu()` fills from the `WC_WALL_PRODUCTS` array (~`script.js:17408`).
To add a WC product you add an array entry, not HTML:

```js
{
  productId: "CLPWCF10",
  image: "./assets/CLPWCF10.jpg",          // or images: [a, b, c] → carousel
  fallbackName: "Stand-Flachspül-WC clivia V2 plus …",  // shown until the DB name loads
  category: "floor",     // "accessory" | "wc" | "seat" | "floor"
  montage: "Bodenmontage",                 // omitted ⇒ "Wandmontage"
  // "wc" only: seatId: "CLSIAS", requiredSeatHeight: "erhoeht"
}
```

What the fields do:
- `category: "accessory"` → group *Produkte für Wandmontage*, **checked by default**
- `category: "wc"` → group *WCs für Wandmontage*, mutually exclusive (picking one
  greys out the others), pulls in its `seatId` tile automatically
- `category: "seat"` → rendered inside its WC's pair, driven by the WC selection
- `category: "floor"` + `montage: "Bodenmontage"` → group *Produkte für
  Bodenmontage*, user-driven, no exclusivity
- `requiredSeatHeight: "erhoeht" | "normal"` → tile only visible for that Sitzhöhe

Name and price are fetched per tile from `/api/products/<productId>` and overwrite
`fallbackName`, so **Step 1 is mandatory** — otherwise the tile shows the fallback
text and no price. Kid lists (§2.3) still apply; `wireTileQty` does not (the
generated tiles wire themselves).

Switching Montageart unchecks the hidden side's tiles so nothing invisible prices.

## 5. Sub-groups: "Erforderliches Zubehör" and friends

A sub-group is just a wrapper div inside the panel plus a bit of sync logic. Two
patterns exist — copy the one that matches.

### 5a. One main product → one accessory (1:1)

Model: `initOnshbAutoAccessory()` (`script.js:17180`), tap ONSHB → rosette
YNORGH21825.

HTML inside the panel, after the main tiles:

```html
<div id="myRequiredWrap" class="muted" hidden aria-hidden="true" style="margin-top:8px">
  <div class="subheader">Erforderliches Zubehör</div>
  <div style="display:flex;gap:14px;flex-wrap:wrap">
    <!-- accessory tile(s), §2.1, name="optMyAcc[]" -->
  </div>
</div>
```

JS — one small function, called from the same place as the others
(`initOnshbAutoAccessory()` is called at ~`script.js:17381`):

```js
function initMyAutoAccessory() {
  const reqWrap = document.getElementById("myRequiredWrap");
  const main = document.getElementById("opt_MAIN");
  const qMain = document.getElementById("qty_MAIN");
  const acc = document.getElementById("opt_ACC");
  const qAcc = document.getElementById("qty_ACC");
  if (!reqWrap || !main || !qMain || !acc || !qAcc) return;   // never throw on missing HTML

  const dispatch = (el) => {
    el.dispatchEvent(new Event("input", { bubbles: true }));
    el.dispatchEvent(new Event("change", { bubbles: true }));
  };
  const show = (el, v) => {
    el.hidden = !v;
    el.setAttribute("aria-hidden", String(!v));
  };

  const sync = () => {
    if (!main.checked) return;
    if (!acc.checked) { acc.checked = true; dispatch(acc); }
    qAcc.value = String(Number(qMain.value) || 1);   // mirror the quantity
    dispatch(qAcc);
  };

  main.addEventListener("change", () => {
    show(reqWrap, main.checked);
    if (main.checked) sync();
  });
  qMain.addEventListener("input", sync);
  show(reqWrap, main.checked);      // initial state, e.g. after restoring an offer
}
```

`dispatch()` is not optional: `updatePricing` and `wireTileQty` listen for
`change`/`input`, so a silently set `.checked` never reaches the price.

No localStorage needed — the generic restore path rebuilds the state from the
saved `qty_*` values.

### 5b. Several interchangeable main products → shared accessories (N:M)

Model: `initBasinAutoAccessories()` (`script.js:16428`) — any of CL60 / CL65 /
CL55 / ON35 / COAIR40 opens `#basinRequiredWrap` and fills WTBF, RSL (= sum of
basin quantities) and EV (= sum × 2, labelled in "paare").

To add another main product there you only touch two spots:

```js
const coair40 = document.getElementById("opt_COAIR40");
const qCOAIR40 = document.getElementById("qty_COAIR40");
// …
const basins = [
  …,
  { key: "coair40", cb: coair40, qtyInput: qCOAIR40 },
].filter((b) => b.cb && b.qtyInput);      // tolerates missing HTML
```

State persistence loops over `basins`, so nothing else to add. If you add a main
product to that panel, also list its `opt_` id in the `wireBasinRequired()` array
(`script.js:~18162`) — that is what keeps the Zubehör box open.

To add a further *accessory*, add its tile (§2.1, group `optBasinAcc[]`) and, if
the quantity should follow the basins, one block in `applyRuleFromBasins()`:

```js
if (myAcc.checked) { qMyAcc.value = String(total); dispatch(qMyAcc); }
```

### 5c. "Optional zu …" (visible but not auto-selected)

Same as 5a/5b minus the auto-check: put the tiles in a `<div class="full field">`
with its own `.subheader` inside the required-wrap (see *Optional zu Waschtisch
ohne Unterschrank* in `menu_BASIN`). Nothing else needed — the user picks it,
`wireTileQty` handles the Menge.

### 5d. Menge and price behaviour, summarised

| Want | Do |
|---|---|
| Fixed price per piece | `Products.price` (net). Nothing in the HTML. |
| Default quantity 1 on check | automatic (`wireTileQty`) |
| Quantity mirrors another product | pattern 5a (`qAcc.value = qMain.value`) |
| Quantity = 2 × main (pairs) | `qEV.value = String(total * 2)` — see basins |
| Fixed quantity, not editable | set `value="2"` and add `readonly` to the number input |
| Free price + text (one-off) | no code at all: **Sonderprodukte** panel (`menu_SONDER`) |

## 6. Verify (2 minutes, in the browser console)

```js
// 1. jump to the Optional tab without clicking through the wizard
const sec = document.getElementById('page-Optional');
document.querySelectorAll('section.page').forEach(s => s.hidden = (s !== sec));

// 2. open a category (the card intercepts the click and opens the modal)
document.getElementById('cat_BASIN').closest('label.image-check').click();

// 3. tick the new product
const cb = document.getElementById('opt_COAIR40');
cb.checked = true; cb.dispatchEvent(new Event('change', {bubbles:true}));

// 4. it must be inside the form, else it is never saved
document.getElementById('form-optional').contains(cb);            // true

// 5. it must be in the payload with its qty
formToObject(document.getElementById('form-optional'));           // opt_/qty_COAIR40 present

// 6. price known?
await (await fetch('/api/products/COAIR40')).json();              // { price: 73.13, … }
```

Then check visually: Menge field appears, badge on the card counts up, chip shows
in "Ausgewählte Optionen", any Zubehör box opens, and the Kostentabelle shows the
line with the right price. If the line is missing from the PDF but present in the
Kostentabelle, the problem is never the PDF — both read the same `pricing.js`
output.

## 7. Pitfalls, in the order they bite

1. **Product not in `Products`** → tile works, price 0, line silently missing.
   Always Step 1 first.
2. **id typo** → `opt_COAIR4O` (letter O) prices at 0. Copy-paste ids, never retype.
3. **Only one of the two category maps** → modal doesn't open, or deselect
   doesn't reset. Both: `map` (~17221) *and* `CAT_MENU` (~20227).
4. **Only one of the two kid lists** → card unchecked after reload, or after a
   deep-linked pick. Both: ~14075 *and* ~18106.
5. **Forgot `wireTileQty`** → no Menge field, quantity stays 0.
6. **Input outside `#form-optional`** → never collected, no error anywhere.
7. **Setting `.checked` without dispatching `change`** → UI right, price wrong.
8. **id-scoped `display:` CSS on a panel** → panels are all children of one modal
   body, shown via `.opt-modal-panel.is-current`. A rule like `#page-Optional
   .wc-menu { display: grid }` out-specifies the hide rule and the panel appears
   inside *every* category dialog — with live, priceable checkboxes.
   `#page-Optional .opt-modal-panel:not(.is-current) { display: none }`
   (index.html, inline `<style>`) now guards this; don't work around it.
9. **Panel edited in the modal markup** → there is no modal markup. Edit the
   panel where it lives in the source (§2.1 note).
10. **`price` entered gross** → everything downstream is net; VAT is added once,
    later. Vigor's `grosPrice` is never what goes into `Products.price`.
11. **New CSS in `style.css` has no effect** → `index.html` loads `style.css`
    first and then a large inline `<style>`; at equal specificity the inline block
    wins. Put Optional-tab tweaks there or scope with an id.
