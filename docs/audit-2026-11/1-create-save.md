# Audit 1 — Creating an offer and saving it (client + server)

Code base: worktree `fix-session-recovery-loss` (= `main` + 2 offline fixes). Paths relative to `src/`. `script.js` = `public/script.js`.
Method: static code reading only (no server, no DB, no runtime test). "Verified" = the code path was read end to end; anything not confirmed that way is marked **unverified**.
Not repeated here (already in `docs/research/2026-11-ipad-offline.md` §3/§5): session-recovery snapshot loss, SW `Vary: Origin`, OfflineSaveQueue modes a–k, no server autosave, new document per draft save, no user field.

Counts: critical 1 · high 6 · medium 10 · low 7 (24 findings).

## How the flow actually works (needed to read the table)

- A **draft** (`POST /api/drafts`) is insert-only: unique `(offerType, name)`, no update, no delete route (`routes/drafts.js`).
- A final **offer** (`POST /api/offers`) is never saved by an explicit "save" action. It is a side effect of `saveFinalOfferSnapshot()` after PDF download, e-mail send, Bitrix upload, postal send and sign-on-site (`script.js:5518, 6058, 6123, 27273, 27431, 34031`, `EmailManager.js:1821`). Every such save sets `locked: true` (`routes/offers.js:540`).
- A locked offer number pins the price: `computePrices()` returns the stored snapshot for that number regardless of the payload (`logic/pricing-core.js:2903-2908`). This applies to `/api/price`, all document routes and both save routes.
- The offer number is `ANG<yyyy>-<MMdd>-<HHmmss>` from the device clock (`script.js:2449-2456`), kept in a hidden input `#offerNumber` (`index.html:2598`).
- Restore is an allow-list of per-page handlers (`script.js:19599-19631`, `RestoreManager.js:194-202`); it does not reset the form first.

## Suggested order

1. F03, F04, F07, F12, F09, F10 — small, independent, directly prevent loss.
2. F01 server guard + F06 single number + F14 — stop wrong-price / untraceable documents.
3. F05 reset-before-restore (with a regression pass per offer type).
4. F02/F13/F08 together as "offer identity and state" (one number, real sent state, server-issued) — this is the structural piece and fits the server-autosave work (S2).
5. F15/F16 for speed.
