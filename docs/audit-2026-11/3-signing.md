# Audit 3 — Signing the offer (on-site iPad + customer link)

Code base: worktree `fix-session-recovery-loss` (= main + 2 offline fixes). Read-only review, nothing executed.
Paths are relative to `src/` unless stated. All findings verified by reading code unless marked **unverified**.

Counts: **critical 2 · high 8 · medium 12 · low 8** (30 total)

## Flow diagrams

```
(B) LINK BY E-MAIL
 Rep: Zusammenfassung -> "Senden"  (EmailManager.js)
   POST /api/email/send                       routes/email.js
     |- createSigningRequest(force:true)      routes/signing.js:317   token = 24 random bytes hex, expires +56 d
     |    |- reuse if same offerNumber + identical payload JSON, else NEW request (old stays valid)
     |    '- Bitrix timeline "Signatur-Link versendet" + link in clear text
     |- render offer DOCX -> PDF (or the rep's hand-edited DOCX)   <- what the customer receives
     '- SMTP send, {{SIGN_LINK}} replaced
   afterwards (client, best effort): saveFinalOfferSnapshot -> POST /api/offers (locks price)

 Customer: GET /sign/<token>                  public (authGate.js:28-35), static signpage/index.html
   GET  /api/signing/<token>                  -> prefill + doc list; first call sets openedAt + Bitrix comment
   GET  /api/signing/<token>/documents/<key>/html
          -> getOfferRenderData(snapshot)  = pricing.computePrices() + mapData()   (re-computed per view)
          -> buildAngebotHtml()  (separate HTML renderer, NOT the DOCX)
   per document: POST /api/signing/<token>/documents/<key>  {signatureImage, editedFields, extraFields}
          validate -> Bitrix comment -> [last doc: N x HTML->PDF -> SMTP -> Bitrix upload
                      -> per-contact filing -> deal stage move] -> sr.save()   <- persisted LAST
   Done card: "Sie erhalten in Kürze eine Kopie per E-Mail"

(A) ON SITE (iPad)
 Rep: "Vor Ort unterschreiben (iPad)"         script.js:27392
   confirmBeforeSend -> saveFinalOfferSnapshot (error swallowed) -> POST /api/signing {sendEmail:false, via}
   409 needsConfirm -> window.confirm -> retry with force
   window.open(link)   -> browser: new tab / iOS shell: replaces the OC page in place
 Customer on the rep's iPad: identical page and API calls as (B); every step needs the network
 Back: small "Zurück zum Konfigurator" link -> full reload of /?offer=<nr>

 Expired link: 410 -> "Neuen Link anfordern" -> POST /request-new-link -> Bitrix task (fixed user IDs)
               -> rep must open the offer and re-send the e-mail by hand
 Rep feedback: Bitrix timeline comments + deal stage move (+ bcc if SIGNING_OFFICE_EMAIL set). Nothing in OC.
 Signed PDF: generated on the fly, attached to e-mail + Bitrix. Never stored by the app.
```

## What is fine

- Token: `crypto.randomBytes(24)` hex, unique index; unknown token gives 404, no enumeration by offer number on public routes (`routes/signing.js:368`, `:588-594`; `/status/*` stays behind login, `middleware/authGate.js:28-35`).
- A signed document cannot be re-signed once saved (`routes/signing.js:786-788`) — subject to S-06.
- Customer-edited text fields are escaped on output (`templates/signing-docs.js:28-34`, `:165-167`).
- Bitrix failures are logged with parameters and can be replayed from admin (`routes/bitrix.js:162-170`, `:263-272`).
- Expired page offers a one-click request and is claimed atomically (`routes/signing.js:630-635`).
