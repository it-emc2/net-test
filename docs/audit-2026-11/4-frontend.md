# Audit 4 — Frontend runtime performance and maintainability

Code audited: `.claude/worktrees/fix-session-recovery-loss/src/public` (read-only). Paths below are relative to `src/public/` unless they start with `src/` or `tests/`.

## How the numbers were obtained

- **Static**: grep / Python counts over the source files.
- **"jsdom run"**: `index.html` + `script.js` booted in jsdom (same approach as `tests/unit/scriptBoots.test.js`: `fetch` stubbed to resolve instantly, dynamic `import()` stubbed), with counters on `addEventListener`, `getElementById`, `querySelector(All)`, `dispatchEvent`, `setTimeout`, `fetch` and `buildPayload`. These are **counts of work the code requests**, not iPad timings. Boot count of `/api/price` in jsdom is 83; the real-browser measurement in the earlier report is 56–68, so treat jsdom counts as correct to within about ±30 %.
- Nothing was measured on an iPad. Millisecond figures are not given unless stated as estimates.
- rrweb is not installed in the local `node_modules`, so its bundle size and event volumes are **unverified**.

### Checked and not a problem

- Blob URLs: 10 `createObjectURL`, 10 `revokeObjectURL` in `script.js`; preview URLs are revoked (`script.js:5617-5626`).
- In-memory caches (`script.js:8030, 10865, 12172, 12472, 32032`) are keyed by product/article id and stay small.
- `localStorage` writes on input are small values (`script.js:8541, 8907, 11415` …); no large synchronous JSON per keystroke in `localStorage`.
- App MutationObservers: only `OfferOverrides.js:224` (body class) and `recorder.js:121` (toaster) — cheap.
- Persistent `setInterval`: only `OfflineSaveQueue.js:449` (F-15) and `recorder.js:161`; the two in `script.js` (`:5472`, `:24497`) are cleared.

## Path to split the frontend without a big-bang rewrite

| Step | What | Why first | Effort |
|---|---|---|---|
| 0 | Safety net: (a) golden-payload tests — fill a jsdom form per offer type from a fixture and snapshot `buildPayload()`; restore the snapshot and compare; (b) one Playwright smoke per offer type; (c) counters as budgets in CI: price calls per boot / start / reset, listeners after 5 navigations; (d) CI job that runs tests before `flyctl deploy`; (e) ESLint on `src/public` with `no-undef`, `no-redeclare`, `no-unused-vars` only. | Every later step is checked by this.
