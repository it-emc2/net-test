Postal flow (public/script.js:33892-34075 -> routes/post.js:370-590): client renders the PDF via `/docx-template/pdf`,
base64-encodes PDF + attachments + Bitrix docs into ONE JSON body -> `/api/post/send` -> lock (PostalSend, 2 min / 24 h)
-> onlinebrief24 `POST /printjobs` -> Bitrix comment -> client `saveFinalOfferSnapshot` -> `showSentDialog(via:"post")`.

Server-side work in steps e-m is fully synchronous inside one HTTP request; the code itself notes it "has taken >60 s"
(routes/email.js:473-474) while the client gives up at exactly 60 s.

## What a clean design looks like (one paragraph)

One server-side `OfferSend` record per attempt, created before anything leaves the house: user, deal, offer number, recipient/CC,
the exact payload, the pricing used, the generated files (or their hashes), and a status per step (pdf, smtp, imap, bitrix, stage).
The HTTP request only enqueues it; the client polls. "Sent", the price lock, the Bitrix filing retry, the signing documents and the
SentOfferBar all read from that record. This removes S-01 to S-05, S-12, S-13, S-15, S-17, S-18 and S-24 together.
